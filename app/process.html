Team Ownership Simulator: how I built it

Nitish Savadakar · AI product case study · 90 minutes
1
Understand

Brief → checklist

Turned the brief into 14 testable requirements: ≥2 connected scenes, 3–5 min, replay and restart, clear to use.

2
Design

Model before code

Alex = two numbers, ownership and trust. Five kinds of help, each changes them differently.

3
Write

4 scenes as data

Text and rules in one place. Later scenes read Alex's state, so earlier choices change them.

4
Build

One HTML file

Small engine: show scene → apply choice → pop-up → next. Snapshot before every scene, saved in the browser.

5
Check

Test every path

Script clicked all 192 paths + 24 button checks. Reviewed screenshots, corrected the AI output.

Decisions and checks

  • Main decision: fixed text and simple rules, no live AI model. Reliable on every path, and the brief allows it.
  • AI output corrected: the first draft made "coach" the best answer in every scene. I changed scene 3 so removing the obstacle is best and coaching there lowers trust.
  • AI output rejected: using ready-made website templates. They were not built for a choice-based app.
  • Checked: the AI wrote a test that clicks all paths. I did not rely on reading the code alone.
  • Refined: a home page with urgent situations for busy managers, clickable choice dots, professional wording.

Tools and shortcuts

  • Claude Code (Opus) · HTML, CSS, JavaScript · browser localStorage · headless Chrome for tests
  • Shortcuts: the numbers are my judgement (a psychologist should set them), English and German (German needs a native review), one Alex, not yet tested with real managers
  • Next: test with 3 managers, tune the rules with an expert, then consider a free-text Alex
